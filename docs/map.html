input implemented and in use implemented, not in use built, with a known gap vs the references

[0] Data prep

          This is to convert the raw 3D data into a form that the model can more easily learn from. Three operations here are:
          1. Reframe by treating the camera pose at frame-0 as origin. rel[t] = E[t] @ inv(E[0]).
          2.Normalise meters per-clip, from observed frames only: percentile 
          depth clip, inlier centroid, max centred norm. Makes a tabletop and a
          street land in the same box.
          3. Futher scale by a global scaling_factor (TRAJ_SCALE) to make the denoising target have std ≈ 1.

[1] Visual encoder — step 3

DINOv3-S (frozen) for every frame once, and NOTHING ELSE. The output is
the backbone's raw patch grid, at the backbone's own width (384 for
ViT-S/16), which is what the cache stores.

We can encode each clip once and reuse it for every epoch and every
cutoff. The catch is storage as features are far larger than the video.

The cache boundary is drawn here on purpose: cache what is frozen, train
what is learnable. Anything downstream of this line is trainable, so it
must not live in encoder.py -- preprocess.py runs that file once and
throws the layers away.

The paper's spec says: take MULTIPLE backbone layers, concatenate them,
and upsample 2x. Half of that exists -- `preprocess.py --layers 6 12`
concatenates layers -- but it is UNUSED, because it needs its own cache and
because reading genpt's config showed it is not what the references do.

The upsample half is not built, and it is the half that matters. At 384px
with patch 16 the grid is 24x24, so one patch covers a 16x16 pixel block:
an EFFECTIVE STRIDE OF 16. CoTracker3 (`stride=4`) and genpt
(`encoder_stride: 4`) both run at 4. That is 16x more spatial cells, and it
bounds how precisely any of the matching below can localise a point.

Note a ViT cannot give a pyramid the way a CNN does: every layer is the
same 24x24 resolution, so picking layers varies DEPTH, not resolution.
Finer needs a bigger input image (768px -> 48x48) or a DPT-style
upsampler.

[1b] Feature adapter

Two trainable layers, inside PointDiT. They turn the cached backbone grid
into what [3] and the cutoff actually consume:

  frame_proj   Linear(384 -> D). Not a resize -- each of the D outputs is
               a learned mix of all 384 inputs, so this is where the model
               learns what to read DINOv3 for.
  patch_pos    each patch's 3D position, Fourier-encoded and ADDED to its
               feature. TAPIP3D's feature cloud: the feature says what is
               at a patch, this says where it is. Positions come from the
               cache in metres and are normalised with the trajectory, so
               patches and points share one coordinate space.

Both sit before the sum, and that is the point: W(f + p) = Wf + Wp, so
nothing downstream can rebalance "what" against "where" once they are
added. The balance has to be learnable on this side of the +.

These layers used to sit at the end of encoder.py, upstream of the cache.
Training could never reach them, so the model's entire interface to the
visual world was frozen at random initialisation -- and each preprocessing
run rolled its own, so a cache built over several jobs held clips in
mutually unreadable feature spaces.

The [4c] cutoff replaces the adapter's output, positions included, so a
masked frame gives up where as well as what.

Masking Feature Map

Here we recieve the entire feature map for a frame, and we decide to mask it or not.
This is what allows us to switch between tracking and forecasting for training. 
We cutoff the video at a random frame and feed a null embedding to the model. The
learned ∅ means exactly "nothing here", and RoPE still tells the model
which frame it is, so one shared vector covers every masked frame.
Then at inference, we mask it deliberately too (like pass the null embedding) to ask for a forecast.

[2] Path tokeniser

Converts each noisy 3D position predictions diffused out by the model (the path guess by the model) into a token. It is a nn.Linear(3, D) on the noisy 3D position. Point-space diffusion with no VAE and no grid.

[3] Conditioning vector c

At this stage, we recieve the DINOv3 feature at the query point and its positional embedding and the embedding of noise level and combine these into a single vector to feed into the DiT blocks. c = [DINOv3 feature at Q] + [pos-emb of Q] + [emb of noise level k] It enters through AdaLN (AdaRMSNorm) instead of added to the tokens. This is the standard for DiT apparently. I dont fully understand what this implies yet so I will leave it as a note to myself.

[4] DiT blocks

Tokens form a (T frames) × (N points) grid, so attention is factorised into two cheap slices instead of one T·N blob. a. Temporal, causal — one point across time; frame t sees only t' ≤ t. Reshape (B·N, T, D). b. Spatial — all N points within one frame. Reshape (B·T, N, D). c. Cross-attention (step 3) — each point queries its frame's feature map. RMSNorm, QK-norm, GEGLU FFN. RoPE on time; axial RoPE on query xyz. 4c is the tracking/forecasting switch: masked frames get the learned null embedding ∅ instead of C_t. Same machinery, no branching. Cross-attention was chosen over correlation features on the grounds that correlation needs a template matched against a real image and forecasting has no image. THAT REASONING WAS WRONG, and an ablation proved it: with cross-attention alone the model scored the static baseline whether it was given the right video or another clip's. Correlation is now computed as well (see Visual matching), and a masked frame simply zeroes it, exactly as ∅ does for cross-attention. Paper sizes: 6 blocks / dim 384 (main), 12 / 768 (Kinetics). Ours: 18.35M params at dim 256 / depth 6 / 4 heads. genpt uses 8 heads and mlp_mult 2; we use 4 and 3.

[5] Output heads

A "head" is a small output layer converting a hidden vector into the format we want. Position — Linear(D → 3), predicts the velocity x1 − x0. Loss is l21 by default, weighted per point so the error is measured in units of the APD threshold (`apd_weight`, after TAPIP3D's `scale_loss_by_depth`). Visibility — Linear(D → 1) with BCE on the ground-truth visibility — is NOT BUILT. The model has only the position head. Consequence: of the benchmark's three headline metrics we can report APD and neither AJ (which requires the visibility call to be right) nor OA (which is purely visibility). It would not improve APD; it makes results reportable. Visibility means geometrically occluded or off-screen, and would be predicted for every frame including forecast frames — a forecast point is not automatically invisible.

Visual matching — M1, M2, M3

Three separate ways the model relates a point to the image. All three are
recomputed at EVERY sampling step, because all three read the current
estimate x, which the sampler updates 50 times.

[M1] LOCALITY BIAS  (run5, APD 0.274 -> 0.294)
  dist2 = |x - patch_xyz|^2 for all 576 patches, added to the
  cross-attention logits as -dist2 * softplus(w), one learnable w per
  block. Prefers patches near where the point currently thinks it is.
  NOTE: this contains NO PIXELS. x and patch_xyz are both geometry, so it
  narrows the search without carrying any information about the image --
  which is why the ablation still showed the video being ignored after it.
  Equivalent in spirit to DELTA's ALiBi-style spatial bias.

[M2] GLOBAL CORRELATION  (run6, 0.294 -> 0.354)
  corr = corr_q(id_card) . corr_k(context), one score per patch, on RAW
  backbone features. Used twice: added to the attention logits so
  appearance steers the lookup, and softmaxed over patches to give a
  weighted-average patch position -- "where in this frame does the query
  appear" -- fed into [3].
  This is what made the model actually read the video: after it,
  swapping in another clip's frames drops APD BELOW the static baseline.

[M3] COST VOLUME  (run9, running)
  8 support patches nearest the anchor at frame 0, correlated against the
  16 patches nearest the current estimate, giving an 8x16 table, plus each
  neighbour's offset from x. MLP -> 256 -> [3].
  Why: one score per patch throws away WHERE INSIDE the neighbourhood the
  match peaks and how sharply. CoTracker3 and genpt correlate a 7x7 support
  window against a 7x7 crop and MLP the 49x49 result
  (`genpt_fm.py:147`); their conditioning IS that correlation
  (`genpt_fm.py:365`) and they have no patch cross-attention at all.
  We take k-nearest in 3D rather than a square image crop because our
  estimate lives in 3D and we never project -- TAPIP3D substitutes the same
  way in knn_feature_4d.

Each is switchable: --locality 0, --correlate 0, --costvol 0. All three
create no parameters when off, so older checkpoints still load, and every
gate initialises at ZERO so an untrained model reproduces the previous one
exactly.

Known gaps vs the references

Read from source, not from abstracts: configs/model/genpt_fm.yaml and
cotracker3_online.py:45-49. genpt is the closest reference (same method,
full code) and ITS CONFIG IS COTRACKER3'S, so the evidence behind these
numbers is CoTracker3's published results.

                      CoTracker3   genpt    ours
  encoder             RAFT CNN     RAFT CNN frozen DINOv3 ViT-S/16
  stride              4            4        16          <-- biggest gap
  correlation window  7x7          7x7      k-nearest in 3D
  query template      window       7x7      8 support patches
  pyramid levels      4            3        1
  virtual tracks      64           64       none
  causal mask         n/a          False    True (measured better for us)
  refinement (train)  --           4 steps  none
  losses              --           coord + vis + conf   coord only

FINE STRIDE AND LOCAL CROPPING ARE COUPLED. A correlation tensor is
(B,T,N,P); at stride 4, P=9216 and that is ~1.8 GB. Cropping is what makes
the resolution affordable, so "upsample 2x" was never a standalone change
-- M3 is its prerequisite.

Also unbuilt: the visibility head (blocks AJ and OA), diffusion forcing
(`flow.py` already accepts per_frame_k), autoregressive sliding window
(nothing to slide on 24-frame clips), and point-count factorisation.

One open puzzle, not a gap: our loss and our metric disagree. Bidirectional
attention cut val_loss 0.278 -> 0.212 while APD fell 0.388 -> 0.375, on the
SAME val clips. The loss is a continuous error; APD is a threshold count.
Every reference reparameterises the target -- DELTA predicts log(d_t/d_1)
and ablates it against inverse and Euclidean depth -- and we regress raw
metric 3D.

Training

Conditional flow matching. x_k = (1−k)·x0 + k·x1 with x0 ~ N(0,I); predict x1 − x0. k comes from a logit-normal (loc −1, scale 1.5), not uniform. The paper reports this as critical, and SD3 found the same. The switch that controls everything is whether frame t has visual conditioning. t < T_C gives tracking (conditional). t ≥ T_C replaces the features with ∅, giving forecasting (unconditional). T_C = T is pure tracking, T_C = 1 pure forecasting. No architectural change, just a mask. Deferred past step 4: diffusion forcing (independent k per frame), autoregressive sliding window, point-count factorization.

Current decisions

Frozen frame-0 camera frame. Everything expressed in frame 0's camera, never re-anchored. Static like a world frame (ego-motion removed), but constructible from relative poses alone, which is all real video gives you. Costs the gravity prior — "down" is no longer a fixed axis. MotionForesight freezes the last observed frame instead; we use frame 0 because our T_C is random per sample and a moving origin would make targets depend on the mask. Camera pose is an input, never predicted, never a token. Used only as geometry: unproject depth to 3D, project 3D to 2D for feature sampling. Absolute positions, not residuals. Tried MotionForesight's residual parameterisation and dropped it — they get away with it because they denoise in VAE latent space. The anchor is kept as conditioning instead. Two scales. Per-clip scene scale for geometry; one global TRAJ_SCALE for the denoising target. Global, not per-clip, so a fast clip stays genuinely faster than a slow one. Query = 2D pixel + source frame index. The pixel is a pointer: used to sample the DINOv3 ID card and look up depth for the 3D anchor. The tokens the model denoises are 3D. Feature-cloud conditioning in from the first real test. Free on Kubric (GT depth + pose). "Remove pointmap conditioning" is a planned ablation.

Where the code comes from

The paper's own repo is empty ("coming soon"), so: DiT block, AdaRMSNorm, RoPE, QK-norm, GEGLU, zero-init, temporal/spatial factorization — from tesfaldet/genpt, src/models/networks/transformer_genpt.py. Feature cloud / 3D lifting — from TAPIP3D. Cross-check only — facebookresearch/DiT (ICCV'23) and co-tracker. On genpt: arXiv 2510.20951, authors include Adam Harley (PIPs / PointOdyssey, who defined modern point tracking) and Chris Pal (Mila). Its transformer descends from HDiT (Crowson et al., ICML 2024). We take engineering from it, not claims — every mechanism was chosen from the CVPR spec first. Not reused: genpt injects image info as correlation-pyramid features through AdaRMSNorm. We need cross-attention so ∅ works for forecasting.
